# BOUNDARY — 生产单档的边界目录（⑤′-2，2026-08-23）

生产单档：`gemma-4-26b-a4b-it-4bit`（定档 2026-08-23 用户拍板，暂且）。本目录回答一个问题：
**哪些请求形状已知是这一档做不好的、凭什么这么说、命中了该怎么办。**

- **谓词是代码**：`backend/framework/cloud/boundary.py`（`CATALOG`）——每条一个对请求侧事实
  （文本/带图/上下文长度/显式要求）的确定性谓词，生成前可判。本文档每条 `### B<n> · \`id\``
  与代码一一对应（金测试 `tests/test_boundary_catalog.py` 钉 id 集合与状态字样一致）。
- **证据先于条目**：状态 `confirmed`（探针/横评实测）/ `weak`（间接证据或单例）/
  `pending`（探针未跑完，**不触发升级**）/ `cleared`（探过没复现，留档防重复立项）。
- **动作**：`switch_tier`（换本机静态位：定档里的 vision 特长位 qwen38、长上下文后备 26b-8bit；
  动作若要求生成参数——如换档须开思考——写在代码字段 `action_gen`，不只写散文）、
  `tool_assist`（把本地模型做不稳的那一步交给确定性工具，如 run_math——只提醒模型，零换档零出网）
  或 `cloud_consult`（云端导师 = **商用 API**；铁律 6 只顾问不执行；Colab 与生产无关）。
  `match()` 永不返回 `cleared`、缺省不返回 `pending`，`weak` 由消费方按用途筛（自动档只认
  confirmed）。消费方是 ⑤′-3 升级策略（编排层护栏），本文档不描述触发机制。
- **谓词只看指令**：关键词匹配对用户问法（`RequestFacts.text`），粘贴/摄入材料只作长度信号；
  英文一律字母边界锚定（评审实测 `prove`→improve、`mean`→"what do you mean" 的误报已修）。
- **回流**：`backend/scripts/boundary_harvest.py` 扫生产 `sessions/*/history.jsonl`，按确定性
  信号（status fail/warning、解析错 ≥2、一轮 ≥12 圈、工具错 ≥3、cloud_degraded、用户重发）
  产候选 → `boundary_candidates.jsonl`（**gitignored**，含 prompt 片段）。候选分两类：
  「目录证据候选」（命中谓词且失败 = 条目证据）与「目录盲区候选」（失败但无谓词命中 =
  新条目线索）。候选不是结论：条目升降级永远走人工鉴定 + 探针，脚本不改目录。

### B1 · `vision_chart_numeric` — 图表数值读取（ChartQA 型）

状态：**confirmed** ｜ 动作：`caveat`（答复末尾提醒核对；不换档不出网）。换 `Qwen3.8-27B-4bit` 只作文档建议，由用户按工作形态自行切

  4bit **0.958** / 8bit **0.943**（08-23 生产口径重画像 runs 20260823-140448 / -133216）。
  逐题差分（本波从三份 `results/*/transcripts.jsonl` 算出，零 GPU；run 戳与定义写在
  `benchmarks/data/boundary-probe-20260823/vision_diff.json`，复算脚本同目录 `vision_diff.py`；
  **注意三份来源 run 是 `results/` 下的 gitignored 本地件**——换机只能复核清单本身，不能重算）：**30 题 26b 错而两档 qwen38
  全对**，全部 `vi-chartqa-*`；对称反向（两档 qwen 都错而 26b 对）**5** 题（宽口径"至少一档
  qwen 错而 26b 对"10 题）；三档同错 3 题。
- 谓词：带图 **且** 问法含图表/读数类词（柱状图/折线图/饼图/峰值/最大最小/多少/chart/
  plot/axis/peak/how many…）。带图但非图表问法（"这张照片好看吗"）不命中。
- 探针集：上述 30 题（已有题库子集，不另造）。复核口径：若切档，该 30 题应 ≥ 27 对。
- 为什么不出网：vision 是本机静态位就能解的（qwen38 两档均 ≥0.94），不必出网。
- **为什么不建议换档（用户 2026-08-23 拍板降为 caveat）**：64G 上两档**不共驻**——26b-4bit 64k 满

  半分钟）、之后每轮生成 45 vs 90 tps、prefill 239 vs 1308（慢 5.5×）、做完再换回。收益是 212 题
  差 30 题（一题多对的期望约 1/7）。为一条图表问题换整个生产档不划算；成批看图（整段工作都受益）
  时由用户自行 `./devctl.sh model` 切，目录不代劳。动作文案见 `boundary.py` `action_notice`。

### B2 · `long_context_structured` — 长上下文 × 结构化产出（答复正文）

状态：**cleared** ｜ 动作：`switch_tier` → `gemma-4-26b-a4b-it-8bit`（长上下文×结构化后备；
仅作静态位记录，谓词已按 cleared 恒不命中）

- 立项由来：08-14 哨兵矩阵 26b-4bit tool@32k/64k ✗——但那是 **JSON 工具声明体的旧口径**，
  DSL 迁移后同格翻正（`benchmarks/baseline/20260814-dsl-fullmatrix`：26b-4bit 翻正 32k/64k，
  回退 0）。残留的问题是：**答复正文里**的结构化产出在长上下文下从未被探过。
- 探针：新批 `items/text/longctx_struct.jsonl`（`gen_longctx_struct.py` seed 20260823 确定性
  重建）：12 条设备巡检记录散落在百科体填充文里，nominal 8k/16k/32k/48k（实测 prompt
  7939/15347/30405/45711 token），任务 A = 提取全部记录为 JSON 数组（判分：12 个编号 +
  12 个读数 + 4 个字段名全含）。
- 结果（`benchmarks/data/boundary-probe-20260823/`，26b-4bit 生产口径关思考，spec off）：
  **任务 A 4/4 全过，8k→48k 每档 12/12 记录全中**，prompt tps 1137–1470、gen tps 72–107、
  峰值内存 20.9G。26b-8bit 同口径：**任务 A 4/4 同样全过**（prompt tps 1282、gen tps 64.6、峰值 33.5G）。
- 结论：长上下文×结构化**提取**不是 26b-4bit 的弱项 → `cleared`。哨兵时代的弱信号已被
  DSL 迁移消化。本条留档是为了下次有人再从 08-14 矩阵读出同一"弱信号"时不必重跑。
  探针同时暴露了另一条真正的弱项，见 B3。

### B3 · `implicit_aggregation` — 散落记录的隐式聚合（分组计数/求和，关思考）

状态：**confirmed** ｜ 动作：`tool_assist` → `run_math`（列表交模型、算术交沙箱；零换档零出网）。后备（文档记录、不作动作）：换 `Qwen3.8-27B-4bit` 并开思考（4/4，但慢 4.9–7.8×）

- 发现：同一探针批的任务 B（按状态分组 → 条数 + 读数合计，输出 Markdown 表；判分
  `regex_all` 逐组钉「状态|条数|合计」同行成对——条数与合计都钉，评审后收紧，归档 4 个 run
  按新口径离线重判结论不变，见 `rescore.json`），26b-4bit 生产口径（关思考）**8k/16k/32k/48k
  四档全挂（0/4）**，且不只是算错合计——**每档都有分组条数错**（8k：停机 4≠5；16k：告警
  5≠7；32k：告警 2≠3；48k：告警 2≠4、停机 3≠5），合计偏差从 −3093 到 +1448。任务 A 同文
  同记录 12/12 全中，故不是"没读到"，是**不列中间结果就直接出聚合值**时丢记录、算错和。
  与上下文长度无关（8k 即挂）。
- 对照（动作证据，同批 `-table-think` 变体 = 同题开思考预算 1024）：
  - 26b-4bit 开思考（预算 1024）：**0/4**，且 3/4 题思考通道空产出（`empty_think`，墙钟与关思考逐题相同 6.2/11.8/25.1/41.1s），48k 题 97 字全进思考频道、正文空——本档「开思考」在这类任务上不产生草稿，档内自救不成立
  - 26b-8bit 关思考：**0/4**（8k 停机 4≠5；16k 告警 6≠7；32k 三组条数全对、合计偏 −8/+10/**+477**；
    48k 正常 2≠3、停机 3≠5、告警 2≠4）→ 量化位宽不是变量，换 8bit 无用
  - qwen38-4bit 关思考：**0/4**（8k 三组条数与合计全错、比 26b 还差；16k 只差告警合计 +289；
    32k 停机 6≠5；48k 停机 6≠5 + 告警合计 −275）——关思考时没有可靠优势；**开思考（预算 1024）：4/4 全过**，每题思考 1.56–1.72k 字、条数与合计全对。代价：墙钟 47/75/134/200s vs 26b-4bit 的 6/12/25/41s（稠密 27B prefill 239 tps vs MoE 1300 tps），峰值内存 28.1G（含 MTP 草稿件）
    〔08-24 横评更新：同配置复测 qwen38-4bit `-table-think` **3/4**（16k 挂）、8bit 同 3/4——
    repeat=1 下与 08-23 的 4/4 差一题，「开思考换档可救」从"全过"降级为"多数过"；本条
    后备动作的期望值按此校准。同场更强的新证据：纯 `-table` 变体（无思考、无先列后算）
    七档 × 4 长度 **0/28 全灭**，Ornith-1.5 三档亦 1/12——B3 是全家族通病，run_math
    tool_assist 护栏的适用面覆盖所有在册档。数据：benchmarks/data/model-eval-20260824/。〕
- 谓词：任务要求对多条记录做**聚合**（合计/总和/平均/分组统计/条数/sum/total/average/
  group by/count…）且不是单纯提取。不看上下文长度。
- **「先列后算」探针（2026-08-23 晚，用户拍板先跑再修；`-table-list` 变体 = 关思考 + 指令"先逐条
  列出记录再分组计算"，run `gemma-4-26b-a4b-it-4bit-listfirst/`）**：26b-4bit 四档 **12/12 记录全部
  正确列出（零错零漏）**，但对着自己列出的清单做计数/求和**仍 0/4**——8k 停机 6≠5（多数 1 条）、
  16k 正常合计 3195 vs 4195（差整 1000）且告警合计 5053 vs 5941（差 888）、32k 三组合计各差 1–40、
  48k 告警 3≠4 / 停机 4≠5。
  按"模型所列记录"重算的真值与题目真值完全一致，所以错全在算术/计数这一步。
- 结论：病根比"没有草稿"更窄——**这档关思考时，对一个摆在眼前的 12 行清单做计数和加法都不可靠**；
  不是长上下文、不是量化、也不是提取。两档 gemma 26b 关/开思考都挂（26b 开思考不产草稿；48k 题
  整段答复进了思考频道、正文空，按内容也错 2/2/3≠3/4/5），qwen38 关思考也挂、开思考即全对。
  动作据此定为 **`tool_assist` → `run_math`**：命中即给模型一条提醒「先逐条列出，再用 run_math
  算分组条数与合计，不要心算」——列表这一步已实测 100%，算术交离线 Python 沙箱（确定性、免审批、
  零换档零出网）。**未做端到端实跑**（模型是否听话调 run_math 是行为问题，待生产回流看

  "几十条以上"改为直接塞进 run_math 调用而非逐行列出，但这一分支没有探针；run_math 未注册的主机上
  不出此提醒（决策期查注册表）。换 qwen38 开思考（4/4，慢 4.9–7.8×）降为文档里的后备。
  口径说明：16k 档「停机」只有 1 条，该组合计 = 抄读数，不含算术。
- ⑤′-3 的护栏按本条动作字段执行：`tool_hint` 只进模型尾注，用户面无提示。若将来改回换档建议，

## 维护规则

1. 新条目先有探针与数字，再进 `CATALOG`；`pending` 条目不触发升级。
2. 换生产档（`PRODUCTION_TIER`）= 整本目录失效，全部回到 `pending` 重探。
3. 每次 harvest 产出的盲区候选若能归条，条目证据要引用去标识后的摘要，不贴原 prompt。
4. 动作字段只写实测证明更好的那一档/那条路；没对照数据就写 `cloud_consult` 并标 weak。
