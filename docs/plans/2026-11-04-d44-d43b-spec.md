## Why
- D44 (plan §6 row :392, user 11-03 「先补 schema 按需，缺省值补完再定」): in catalog mode the prefix lists only name + 80-char summary (tool_disclosure.py:149); the model must call `get_tool_schema` to learn parameters, and in b2 it did so 3 times in 80 runs while producing 16 missing-argument errors (ANALYSIS.md:15: run_math 9, rag_search 6, copy_file 1). Production has NO generic argument check: a missing argument surfaces only as `execute(**args)` TypeError caught at registry.py:336, whose text is the exception string **plus the full traceback**, model-facing, with no schema. The fix: a deterministic pre-execution check (required present, no unknown keys) whose error text in catalog mode carries the tool's full declaration, so the retry needs exactly one more iteration and no guesswork.
- D43b (user 11-04 「(i) 免压，随 D44 做」): at the W2 step boundary the result of `file_extract(path="spill:…")` (a read-back the model just paid an iteration for) is compacted again into a stub of the same handle (keep_recent=2) — the read-back is wasted. W2 must leave read-backs alone; the W1 ceiling may still compact them.

## Change 1 — generic argument precheck (backend/framework/mcp/registry.py `validate_call`, :226 area)
`validate_call(name, arguments)` currently only runs the tool's opt-in `validate_arguments`. Add, BEFORE the opt-in checker, a schema check driven by the tool's declared `parameters` (JSON schema: `required`, `properties`, `additionalProperties`):
- `missing` = required keys absent from `arguments` **or present with value `None`** (the model often sends null; the harness stub orch_stubs.py:1045 already treats null as missing, keep both sides identical).
- `unknown` = keys of `arguments` not in `properties`, only when `properties` is a dict and `additionalProperties` is not `True` (and not a schema dict). Skip the unknown check entirely when the tool declares no `properties`.
- If either list is non-empty, return the error text (do NOT call the opt-in checker; do NOT execute):
  `System Error: '<name>' was not executed: missing required argument(s): 'a', 'b'; unknown argument(s): 'c' (accepted: x, y, z).`
  — omit whichever clause is empty; keep the literal phrase `missing required argument` (analyze_orch.py:713 and test_context_knee_analyze_orch.py:91-99 match it) and the `System Error` prefix (analyze_orch.py:712 `startswith`). No traceback, ever.
- Schema feedback: `validate_call` gains a keyword `schema_feedback: Optional[Callable[[str], str]] = None`. When given and the check fails, append `"\nFull declaration of '<name>':\n" + schema_feedback(name)`. The orchestrator passes it only in catalog mode (`self.tool_schema_mode == "catalog"`, orchestrator.py:430), using the same renderer `get_tool_schema` uses (orchestrator.py:1994-2017: dialect `render_tool_declaration`, JSON fallback) — factor that render into a helper both call; the `tool_schema_render_fallback` event stays. In full mode append instead `"\nCheck the tool's declaration and call it again."`.
- Keep the opt-in `validate_arguments` path unchanged for calls that pass the schema check.
- Orchestrator precheck loop (:1463-1478): unchanged apart from passing `schema_feedback`; the existing `tool_error` event with `kind="precheck"` keeps firing. Add to that emit `schema_fed=<bool>` and `missing=<list>` / `unknown=<list>` (truncate lists to 8 names) so the harness can count D44 events from guardrail/journal events; find where `tool_error` events are serialized in the knee harness (`guardrail_events.jsonl`) and make sure the new fields land there.
- Also fix the generic exception path registry.py:336: stop sending `traceback.format_exc()` to the model. Keep `System Error: Exception occurred while executing '<name>': <str(e)>` (first 500 chars of str(e)), log the traceback at WARNING via the module logger instead. (This is model-facing text hygiene; check which tests pin the traceback — report, do not weaken a pin silently.)
- Iteration accounting: none (the feedback is text; the model re-issues the call on the next counted iteration, like parse_error_feedback :57-75).
