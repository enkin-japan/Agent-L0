## Why (b2 batch recomputation, 2026-11-04)
At the W1 ceiling / W2 step boundary a tool observation is replaced by `head[:200] …[Observation compacted; originally N chars]\n全文：file_extract(path="spill:<hash>")` (compactor.py:267-270). In the knee 57K arms each run has 42–69 such stubs; the model has to guess which handle holds the fact it needs, reads back 12–54 handles and runs out of iterations (14/18 read-back runs aborted). Read-back itself works (one call reads a whole observation; 0 truncations in 225 read-backs). The stub must therefore say WHAT is inside: IDs, paths, and key = value assignments that are not already visible in the head.

## Change 1 — clue extractor (new, backend/framework/memory/compactor.py)
```python
def observation_clue(text: str, *, head: str, key_counts: Mapping[str, int],
                     max_tokens: int = 8, max_chars: int = 240) -> str
```
Returns `"; mentions: tok1, tok2, …"` or `""`. Rule R2 (validated on b2 real spills: cards covered 28/28 w1, 30/30 catalog; non-empty clue on 149/504 observations):
1. **Decode** JSON-string escapes for tokenizing only (`\\n`→newline, `\\t`→tab, `\\"`→`"`, `\\/`→`/`, `\\\\`→`\`); never alter the stored head/text.
2. **Token classes** (compile once at module level, `re.ASCII` where digits matter):
   - ID: `\b[A-Z][A-Z0-9]{1,}-\d{3,}\b` (e.g. `OPS-48213`, `SKU-120`).
   - PATH: absolute or relative path with ≥ 1 slash and a final component containing a dot: e.g. `/opt/halyard/conf/halyard-ab12cd.toml`, `conf/app.yaml`; exclude URLs' scheme part (URL and hex classes had 0 matches on b2 — do not add them).
   - ASSIGN: `\b([A-Za-z_][\w.]{2,})\s*[=:]\s*"?([\w./-]{1,64})"?` rendered as `key = value`; skip values that are themselves paths/IDs already captured.
3. **Drop** any token whose literal text appears in `head` (so the observation's own path, already in the first 200 chars, is not repeated); dedupe preserving first occurrence.
4. **ASSIGN singleton rule**: keep `key = value` only if `key` occurs exactly once in this observation and `key_counts[key] == 1` across all tool observations in the compaction range (the caller passes the counts).
5. **Order**: IDs first, then PATHs, then ASSIGNs; within a class by first occurrence. Cap at `max_tokens` tokens and `max_chars` total (stop adding when the next token would exceed; skip a single token longer than `max_chars`).
Pure function, no I/O, deterministic.

## Change 2 — stub template (compactor.py:267-270 and the surrounding `compact_tool_observations_detailed`)
