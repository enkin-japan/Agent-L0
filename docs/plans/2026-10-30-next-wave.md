## 1. iPhone 回前台「从头重放」——改重连游标，不是再做一份存档
**现象**：iPhone 离开 app 再回来，正在进行的轮次从头把进度重放到当前。
**根因（scout 2026-10-30，证据 `AgentStore.swift`）**
- iOS 转后台数秒后系统挂起 URLSession（非 background session，`AgentClient.swift:40-43`），SSE 断。
- 重连走重锚路径（`AgentStore.swift:1640-1644`）：
  `after = min(replayAfter ?? 0, turn.firstSeq - 1 …)`，随后 `cursor = after`——已消费游标被丢弃，
  倒回当前轮次起点；`replayAfter` 只在 loadHistory 设、事件到达时不前进（:986 / :1542 / :1598）。
- 重放首个 `turn_queued` → `resetPreview()`（:1790 → :1929-1938）清空 streamText / liveSteps /
  taskSnapshot，再逐个 token_delta 重新累加 = 用户看到的「从头加载」。
- 违反 PROTOCOL.md:257「客户端记住已消费的最大 seq，带 after 重连即可」与 :312-313；
  客户端自注 `AgentClient.swift:279-280`「由调用方带游标重连」。
- 本地存档**已存在**：`OfflineHistoryStore`（Application Support/OfflineHistory，0600，iOS 加
  `completeUnlessOpen`），`persistCurrentHistory` 每完成一轮落盘，启动 / 选会话先显缓存。
  活跃轮次预览按设计不缓存（`OfflineHistoryStore.swift:4`）。所以「再存一份」不解决问题。
**修法（客户端单侧，不动协议）**
- `attachLoop` 断线分支：只有首次附着才重锚；传输层掉线后用已消费 `cursor` 续播。
- 可选：用 `/turn` 已返回的 `partial_text / partial_thinking / task`（PROTOCOL.md:286-292
  「即时恢复，免重放」）直接补预览，消除续播期间的空窗。
- 顺带核：重放路径 `onTurnQueued` 非乐观分支（:1806-1811）可能多追加一个用户气泡且只
  移除当前 id——写用例验证，是则一并修。
- 守卫：客户端重连用例（断线 → 重连 after == 已消费 seq；首附着仍重锚），变异证明。
