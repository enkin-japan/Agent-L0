## 外部观测负载污染窗：t = 8.49h → 8.79h（墙钟 11:33 → 11:51，约 19 分钟）

**现象**：四条腿**同时**掉 tps 约 10–13%——chat 热轮 ~94.2 → 82–88、tool ~93.7 → ~91、
longchain ~87.6 → 76.2。**同时 TTFT 反而变好**（chat 热轮 0.30 → 0.23–0.27）。

**这不是引擎劣化**，三条证据：
1. 若是引擎/缓存侧劣化，预填（TTFT）会跟着变差，不会变好。「解码变慢 + CPU 侧延迟变好」
   是 Apple Silicon **CPU 与 GPU 共享功耗预算**的指纹：CPU 侧来活抢走功耗预算 → GPU 降频
   → 解码 tps 掉；而 CPU 侧固定开销（HTTP/调度/分词）反而更快。
2. 起始时刻吻合：`Activity Monitor.app` 进程启动于 **11:33:29**，首条劣化行在 **11:33:10**
   （早 19 秒，可由「先开 Launchpad 找这个 app」解释）；其后
   `Activity Monitor` / `sysmond` / `WindowServer` / `PerfPowerServices` 长期占据 CPU 榜前列。
3. **验证性检验通过**：该负载关闭后 tps 立刻回弹——11:51:56 起
   `93.98 / 92.94 / 91.30 / 91.31`，回到正常带内。

**结论**：本次跑在非干扰条件下无劣化；污染窗按上述边界切除，不进判决。
