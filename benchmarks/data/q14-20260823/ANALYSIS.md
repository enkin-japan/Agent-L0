# Q14 受控实验：批压力下的交互延迟（2026-08-23）

跑法：`backend/scripts/bench_q14.py`，26b-4bit（生产缺省候选）、贪心、
INFER_MLX_MAX_CONCURRENCY=4、kv 稠密、离线模式。热身 1 条（弃）→ 臂 A 空载
16 条交互 → 臂 B 批压力下同序同 prompt 16 条（4 路 batch_ok 短行循环重发，
行长 48 tok 按占空比配平使臂 B 窗内持续发生新行准入/预填）→ 臂 A′ 回基线。
判据阈值先登记后开跑（header 内）。产物：q14.jsonl（run 2，判据 PASS）、
q14-run1-invalid.jsonl（run 1，作废但有证据价值，见下）、双跑 server 日志。

## Run 1（作废）：抓到一起真并发事故 → 引擎修复

首跑臂 B 第 8 条交互行失败：`RuntimeError: Already borrowed`——HF fast
tokenizer（Rust RefCell）被单流路执行器线程与批泳道驱动线程并发使用（撞点=
驱动线程准入 tokenize/步末 detok 与交互请求 prompt encode 重叠）。按预登记
作废条件（errors_total 增量 + 交互行失败）整场 exit 3。

修复（`inference/batch_lane.py`）：装配期 `copy.deepcopy(backend.processor)`
给泳道私有 processor——两个 Rust 对象无共享借用，热路零锁；权重照旧共享。
锚测试 + 变异验证（回灌共享实例，锚红）。**这正是本实验存在的意义：
「零并发事故」门在受控窗口内抓到并修掉了一个生产形态必然零星复现的缺陷。**
