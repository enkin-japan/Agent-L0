## 1. 结论

**拐点规则**（`--metric/--drop/--recover/--baseline-levels` 可调）：主指标 Pass^2；基线 = 0 / 4096 档里点估计较高者；
拐点 = 首个「≤ 基线 − 20 点，且其后所有档都 < 基线 − 10 点」的档；没有就记「到顶档未见拐点」。另跑 18 个变体（Pass^2 / 成功率 × 三种基线取法 × drop 15/20/25）看稳不稳。

### Qwen3.8-27B-INT4（远端 vLLM A100）：影响因素排序 MTP（主）> 长度（无拐点）≈ 采样（噪声内）
- **MTP 是主因**。同一采样下 MTP 关→开，在 4 个共同档按题合并：
  - current 采样：成功率 −49 点 [−66,−31]，Pass^2 −62 点 [−80,−45]；
  - card 采样：成功率 −45 点 [−62,−28]，Pass^2 −57 点 [−75,−40]；
  - 两种采样下都是 10 题里 0 道升、9 道降，p=0.004。
- MTP 开时：
  - 回忆从 100% 掉到 42%（current）、52%（card），三个槽同样掉，没有位置差；
  - 复读命中从 0 升到 4 / 5；16K 起 env 错均值从 0.20–0.25 升到 0.55–1.60。
- **0 档就已经掉了**：MTP 开时成功率 65% / 60%，MTP 关时 90% / 85%。按题配对差 −25 点 [−50,+0]（current）、−25 点 [−55,+0]（card），只有 3 道题降，p=0.25，单档区间碰到 0。
  16K 起差值放大到 −40 ~ −70 点，各档区间都不含 0（E 节）。所以 MTP 本身就伤，长上下文下伤得更重。
- MTP 开时的失败形态（D 节、B 节「串台」行）：
  - 主因是终态断言（两种采样各 25 次）、超步数（card 12 次）、无收尾答复（current 11 次），复读只算主因 4–5 次。
  - 末轮正文把填充里的 `legacy-2025q3` 旧项目当成当前任务来答：current 16K、32K 各 6 次；MTP 关时最多 2 次。
  - 有零步即终的 run；有不少 run 给了收尾答复，但回忆零命中。
  - 例子见 qwen-current-mtp 16K：「该文件不存在……」「This file is a valid YAML…」「```\n```」。
- 崩得最重的题（共同 4 档合并的通过 run 数，满分 8，MTP 关→开）：
  - current 采样：lc-hard-008 8→1、005 8→2、001 / 003 / 004 / 006 各 →3；
  - card 采样：001 8→1、004 8→2、005 / 007 8→3。
  - 只有 lc-hard-002（8→7 / 8→6）基本没受影响；lc-hard-009 在关、开两种情况下都是 0，与 MTP 无关。
- MTP 关时**长度没判出拐点**：card 到 57,344、current 到 49,152 都没判出，18 个敏感性变体也都没有。Pass^2 在 50–90% 间抖动；低段→高段按题合并的差，card +2 点 [−10,+18]、current −7 点 [−13,+0]。
  57,344 档受重复行取舍影响（Pass^2 70% 或 50%），结论读作「49K 内无拐点，57K 未定」。
- MTP 关时**采样差别在噪声内**：current→card 合并 Pass^2 −10 点 [−28,+0]；MTP 开时同一对照是 −5 点 [−18,+10]。
- 推断：10-30 复读事故的会话跑在生产 Colab 部署上，那里默认开 MTP（`--speculative mtp`），事故形态（抄错路径、幻觉调用、末次生成复读）与这次 MTP 开时的崩坏一致。但事故会话本身没有关 MTP 的对照，这条是推断，不是测出来的。
- **日文作答不归 MTP**（保留原结论）：MTP 关时，lc-hard-001（zh 题）在 0 档两种采样下的 2 个 rep 都用日文作答。MTP 开时也有假名（card 0 / 32K / 49K 档各 1 次），频次与 MTP 关时同一量级。

### Gemma 4 26B A4B（远端 vLLM A100 fp8，无 MTP）
- card 采样：默认规则判出**拐点 8,192**（基线是 4,096 档的 88%，只有 8 道题），18 个变体给出的范围是 8,192–16,384。
  低段→高段按题合并：Pass^2 −38 点 [−60,−15]，10 道题里 0 道升、6 道降，符号检验 p=0.03。这是全部数据里唯一一个在 95% 水平上分得出来的长度效应。
- current 采样：规则**没判出拐点**，因为 49,152 档回到了基线 −10 点以内。但方向一致：16K −30 点、32K −20 点、49K −10 点；合并差 −20 点 [−43,+0]，p=0.25。
- 退化形态：冗余调用从 0.22 涨到 1.70（card，4,096→32,768）；失败主因大多是终态断言（card 49 次失败里 39 次）。
  回忆漏召**全部是「零命中且没有收尾答复」**，没有一次是单槽漏。这说明退化是执行漂移，不是记忆丢失（推断，与主会话笔记 F8 一致）。
- 按题看，只有 lc-hard-006 随长度失败：0 档和 4,096 档都是 2/2，16K 起全是 0/2。lc-hard-001 各档都失败；lc-hard-010 大多失败，但 8,192 档是 2/2。

### 模型对照（E 节，MTP 关，合并按题聚类）
- Qwen→Gemma：current 采样合并 Pass^2 −30 点 [−62,+8]，card 采样 −14 点 [−41,+17]。16K 起逐档差变大，但每档单看区间都跨 0。两款模型的差主要来自个别题：lc-hard-009 Qwen 0 / Gemma 14（满分 14），lc-hard-001、010 则是 Gemma 弱。
- Gemma 上采样的差也在噪声内：current→card 合并 Pass^2 −2 点 [−18,+15]。

## 2. 不确定度
- 每档 10 题 × 2 rep。Pass^2 的计数单位是题（n=10；4,096 档 n=8），不是委托里写的 n=20。Wilson 区间半宽大约 25–30 点（例：70% → [40,89]）。
- 成功率的 run 级 Wilson 区间假设各 run 独立，但同一题的两个 rep 正相关，所以区间偏乐观。配对差用两段 bootstrap（先按题重抽，再在档内重抽 rep），符号检验按题算。
- 两档里每道题都是 0/2 或 2/2 时，bootstrap 区间会退化成 [+0,+0]（如 qwen-current 32K、49K）。这表示没观察到方差，不表示确定无差。
- 4,096 档基线偏高：缺了 lc-hard-010 r0，这题恰好是 Gemma 的弱题，所以 Gemma 的 4,096 档 Pass^2（88%）偏高。改用 0 档（80%）当基线时，8,192 档正好低 20 点，落在阈值上；drop 取 25 时拐点移到 16,384。
- Gemma 的长度效应只在「合并」这一层分得出来；逐档单看，8,192 档的配对差 −38 点 [−62,+0] 区间还碰到 0。
- MTP 关→开的效应量大，从 16K 起逐档区间都不含 0。但 0 档的差（−25 点）单看不显著，「0 档就已经伤」要靠 0 档与高档同方向这一点来支撑。
- MTP 对照只有 4 个档（0 / 16K / 32K / 49K），没有 4K 和 8K，所以 MTP 开时脚本判出的「拐点 16,384」只能说明在 0 到 16K 之间开始崩，定位不到更细。

## 3. 数据缺陷清单
1. qwen-card 57,344 档：两个客户端并行写入，6 组 (题, rep) 有重复，其中 2 组 pass 不一致（A 节）。该档 wall 不可用；prefill 秒取自首次生成，不受影响。
2. qwen-current 0 档 wall 不可用：与 qwen-card 续跑同时在跑。
3. 4,096 档有 2 个组合确定性报错（lc-hard-005 r1、lc-hard-010 r0，两个模型同样），原因是填充装不下事实卡，按缺测处理。这一档 Pass^2 只算了 8 题。
4. transcripts 里没记 MTP 状态，只能从目录名推断。新批次的目录名必须带 `mtp`，脚本才能识别。
5. 测的 Gemma 是远端 vLLM fp8，生产上的 Gemma 是本机 MLX 4bit（方案 §1.4），这个拐点不能直接搬到生产（推断：4bit 可能更早退化，没测）。
6. harness 的基础 prompt 只有 350–600 tok（B 节 0 档），生产的 system+tools 前缀是 9,424 tok（engine.py:140）。所以 level 基本等于「历史」的规模，没测到生产前缀本身的影响。
7. 连贯判据抓不到不含外文文字的语义乱码（README 已注明），Gemma 连贯率 100% 不能当作答复质量的证据。
8. summarize.py 的成功率和 n 没先去重：笔记 F6′ 里 57,344 档记的是 n=26、成功率 77%，去重后是 n=20、80%。
9. 拐点规则在顶档是空真（见第 1 节）；qwen-probeC 是单 rep、3 道题，不判拐点。
10. 笔记 F8 写的 Gemma 拐点是「16K」；按本规则默认判出 8K，敏感性范围 8K–16K。
11. 笔记 F7 说「日文作答都发生在 MTP 开」，与 qwen-card / qwen-current 0 档的 lc-hard-001 不符（B 节「不连贯归因」）。
12. 连贯率的分母里有「en 题用中文作答」：这些 run 被判不连贯，但答复内容可读。Qwen 85–95% 的连贯率主要是这类语言选择，不是乱码。
13. MTP 两批（qwen-current-mtp、qwen-card-mtp，各 80 行）在同一台 VM 上先后顺序跑完，各自只有一个 stamp，没有重复行，也没有 error 行。没有并发污染，wall 可用。
    MTP 开时首次生成的 prefill 秒偏慢（49K 档 31.2 s，MTP 关时 22.4 s），0 档 wall 偏快（8.2–8.7 s，MTP 关时 13.4 s）。
14. 「复读」失败标签 = 该 run 的 repetition_hits > 0，比终态断言等优先计为主因。MTP 关时这一项全是 0，原来的分类不受影响。
