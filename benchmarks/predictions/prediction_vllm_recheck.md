# 预测：vLLM 26B fp8 MTP 开/关复核场（A100 40G，2026-08-15）

**动机（用户指示）**：搁置扩展/继续优化两案，先验证台账 `EXECUTION_LEDGER.md:835`
（batch6，2026-08-08）的 **1.92×**（139.8→269.0 gen_tps，"k=4"）是否属实；并与
mlx_vlm 对表，裁决跨平台差距能否归结于硬件。顺带裁 §3.1 A9（台账"k=4" vs
vLLM 官方 PR γ=8 的记述冲突）。

**已知背景**：受控口径（61-tok 光合作用 prompt / temp=0 / 400 tok）下，同一颗
A100 上 vLLM 26B fp8 + 官方 assistant 实测 1.41×@γ=4（B5，08-14，AL 2.58，
不带 method 键），与 mlx 26b-8bit 定档 1.41×（block4）**打平**。1.92× 与 1.41×
之差，§5.5 的假说是**负载→接受率**（chat 评测批 AL 拟合 2.7–3.4 vs 受控 2.58）。

## 场设

- VM：CLI A100 40G（`daily.sh start a100` 全链），vLLM 当日 `pip -U` 版（记录进 env.txt）。
- 受控格（`vllm_cell.py`，B5 同口径）：c0(γ=0)、c4(γ=4 无 method)、c4m(γ=4
  method:mtp)、c8m(γ=8 method:mtp)。
- chat 负载（`model_eval` 引擎直连，batch6 同款 tool_call 30 题）：e_off、
  e_on4(k=4)、e_on8(k=8)。gen_tps 取 speed 聚合中位。
- 本地对照（VM 停后）：mlx 26b-8bit + 4bit 草稿件 + block4 + 排序阈值 16 +
  批量走查（1.41× 生产栈），同 tool_call 30 题，off/on 两臂。

**P9 量测口径修订（v1.2，仍先于首跑）**：核对代码后修正——**mlx 路有现成出口**
（backend GenChunk.extra → engine metrics `spec_drafted/spec_accepted`，逐轮进
transcripts.jsonl），mlx chat AL 可直接算：rate=accepted/drafted，
AL≈1+accepted/(drafted/4)（末轮截断带来的偏差 <2%）。反而 **cuda 路 metrics 不带
投机统计**，vLLM chat AL 改为反推 `AL ≈ (on/off 比) × D_vllm(γ=4)≈1.834`（§9.2 表，
bf16 草稿件口径），容差 ±15%。v1.1 写反了方向，以本条为准。

## 判读规则（先写死，防事后合理化）

- P6 成立 ⇒ 「1.9× 属实，但口径是 chat 负载」；差距归因=
  **负载接受率（两侧同向，非平台差）+ 分母 D（§9.3：A100 基线只吃峰值带宽
  45%，并集字节大半被余量吸收；M4 Max 基线已在 76%，字节实打实付费——
  硬件利用率结构差）**。受控同负载下两侧加速比 1.41 vs 1.41 打平 ⇒
  **框架实现不是差距来源**。
- P6 证伪 ⇒ 台账 1.92× 存疑，按 CELL 数据逐项排（γ、版本、题库、并发口径），
  §5.5/§9.5 的"1.92× 是 vLLM 答案"表述要收回或加限定。
- P8+P9 成立 ⇒ "硬件锅"表述成立但要写准：不是"A100 更快"这么糙，而是
  **基线 roofline 占用率不同导致同一份 MTP 字节开销的边际价格不同**。

**机制收束（逐轮分桶，两侧 transcripts）**：
- 短轮（≤30 tok）：vLLM on/off 仅 1.12×、k8 倒亏 36%；**mlx 1.38× 不塌**——vLLM 投机的每请求固定开销远高于 mlx；
- 中轮（31–80）：vLLM 1.46× ≈ mlx 1.45× ≈ 受控 1.41×——稳态下两栈打平；
- e_off 各桶平坦（119–132）：基线带宽受限，长度不敏感 ✓。

**结论**：
1. **1.92× 不属实于当前形态**。它绑定 batch6 当时的负载（~350 tok 长输出、当年题库、vLLM 0.26）；今天生产代表性的短工具调用负载上 vLLM MTP 只有 **1.18×**，k=8 有害。γ=8 假说死（A9 收案：台账 "k=4" 记法成立）。
2. **跨平台差距不能归结于硬件**：同负载同稳态下两栈加速比打平（1.4x级）；短负载上 mlx 反而占优（1.40 vs 1.18）。硬件差体现在**绝对 tps**（基线 142.9/79.7=1.79×，≈带宽比折价后），不在加速比。§9.3 的 roofline 余量论仍解释大 γ 下的 D 差，但生产 γ 档它不改变净比。
3. 判读规则预设的"P6 成立⇒硬件归因"路径未触发；实际走到的是"P6 证伪⇒台账口径限定"分支，且逐轮分桶给出了替代归因（每请求固定开销 × 生成长度分布）。
