# T6b 预测（写于动手改内核之前，2026-08-15）

任务：给 MLX `dispatch_qmv` 的小 M 区间（2..9）加一条 simdgroup-matrix 路
（`affine_qmv_mma`），替换 `qmv_wide` 的逐 lane 标量 FMA 内层。fragment 全 float
（与 steel GEMM 同法、与 qmv_wide 的 float 累加同数值类），寄存器内建 fragment
不过 threadgroup 内存。判据一律「同一份 main(adf21de) 源码、同一自建、开/关
`MLX_DISABLE_QMV_MMA` A/B」，不与 wheel 混比（口径病防线）。

机制依据（§1.4.6，已实证）：4bit 小 M 区间是 ALU/发射受限——字节没多、达成带宽随 M 掉、
拐点随位宽 4:2:1 移动、2bit≈4bit 同耗时；同机 fp16 稠密路 S=2→8 只涨 9%。
故把 M 比例的标量 FMA 换成 MMA 指令应把曲线压平。

## 可证伪预测（bench_mlx_tile.py 口径：31B 四形状 ×60 层，中位 25 次）

| # | 预测 | 证伪线 |
|---|---|---|
| P1 | 4bit M 曲线压平：M=4/M=1 从 1.54× 降到 **≤1.15×**；M=5/M=1 从 ~1.78× 降到 ≤1.25× | 若 M=4/M=1 仍 >1.3×，ALU 论题或 MMA 映射假设错，T6b 按此设计不成立 |
| P2 | 4bit M=6..8 至少省掉 qmv_wide 的第二遍权重读：对 qmv_wide 同 M **≥10% 快**（单瓦片 + 平坦 ALU 双重收益） | <5% 即单瓦片收益被 MMA 固定开销吃掉 |
| P3 | 8bit M=2..5 不倒退：MMA 路相对 qmv_wide **±5% 以内**（该区间本来平坦，MMA 没多少可赚） | 倒退 >5% 则 8bit 档保留 qmv_wide、MMA 只挂 4bit/2bit |
| P4 | 工作集自证：等效带宽 ≤70% 峰值（546GB/s），否则在测缓存，数作废 | — |
| P5 | 数值：对 fp32 参照（先 mx.dequantize 再 matmul）的相对 L2 与 qmv_wide 同数量级（比值 <2×）；生产 31b-4bit 贪心解码输出与 qmv_wide 路的分歧不超过 §1.7 已记录的噪声类 | 超出 ⇒ 接线/公式错，不得进生产 |
| P6 | 端到端：31b-4bit MTP 定档从 **1.547× → ≥1.85×**（§1.4.6 预估 ~2.06×；8bit 草稿件组合 ~2.22×） | <1.7× 则收益预估砍半重记 |
| P7 | 寄存器压力无悬崖：fragment 路每 lane 活寄存器远小于 qmv_wide 的 5×float+5 指针，无 cap9 式占用率崩塌（M 曲线单调平滑） | 出现某 M 突跳 ⇒ 占用率断崖，需查 spill |

## 判定（2026-08-15 晚，全部数据在 `benchmarks/data/t6b-qmv-mma/`）

| # | 判定 | 数 |
|---|---|---|
| P1 | ❌ **证伪**（本预测文件的头号证伪线触发） | 4bit M=4/M=1 = **1.71×**（线是 ≤1.15，红线 1.3）。MMA 路是一条 ~50ms 的 M 无关平线，M≤5 打不过标量 wide |
| P2 | ✅ | 4bit M=6/7/8 对 qmv_wide 同 M **−17%/−31%/−31%**（线是 ≥10%）；M=10-12 −6%~−19% |
| P3 | ❌→按预案处置 | 8bit M=2..5 MMA 倒退 +15~22%（线是 ±5%）→ 定稿为**混合派发**：M≤5 保留 qmv_wide，M≥6 走 MMA（8bit M6-8 −12%~−25% ✓） |
| P4 | ✅ | MMA 平线 197-207 GB/s（36-38% 峰值），非缓存假象 |
| P5 | ✅（终版形态） | fp32 累加版误差**处处 ≤ qmv_wide**（M≥6 全组合比值 ≤1.000，含 M=12/13 双瓦片）。fp16 组内累加变体快 1-3% 但 f16 比值最差 6.1×，判死不用 |
| P6 | ❌ **证伪** | 端到端最优纹丝不动：block3 (γ=2) **1.76×**，两种草稿件、两臂全一致（=§1.6 的 1.75× 复现）。内核把 γ=5/6/7 从 1.21/1.04/1.10 救到 1.63/1.63/1.59（4bit 草稿件）、γ=6 1.10→**1.66**（8bit 草稿件，AL 3.33），但都够不着 γ=2。**2.06×/2.22× 预估的根错误：锚在 γ=4 的 1.547 上，而真实最优早已是 block3 1.75×** |
| P7 | ✅ | 平线平滑无占用率断崖 |

### 机制收案

- 「4bit 小 M 是 ALU 受限」论题**被证实**（曲线确实被 MMA 压平）；
- 但「MMA 指令能便宜地做掉它」**被证伪**：M4 的 simdgroup_matrix 没有专用矩阵硬件，
  微码走同一批 FP 管线。四个结构变体（2SG-16行 / T fragment+双累加器 / 4SG 分 K /
  fp16 组内累加）壁钟时间只动 1-4% —— 总 ALU 发射量是不变量；
- 交付物 = **混合派发内核**（M≤5 wide / M=6..12 MMA）：M=6..12 的量化 matmul
  全场景 +5~30%，γ≥5 MTP 档从死档变可用档（给高接受率草稿件留的保险）。
  仅在 `backend/.venv-mlxsrc`（自建），生产 wheel 未动；上游候选（并入 T7）。

### 场务事故记录（写进 §4 的素材）

三次「重编」实际构建失败（编译错误被 `| tail -3` 吞掉、`pip install` 的管道退出码
被 tail 顶替），我拿 v2 旧二进制连测三轮并在其上编了理论；靠「v5 数值与 wide 逐位
相同不合理」起疑回查 build 日志才翻案。规则：**构建命令必须显式回读 `$?`，bench 前
必须验 `.so` mtime 指纹**。另：评审首审抓到 vec2 载入在零拷贝视图/批步幅下可错位
（Critical，已改回标量载入——steel 同理由）。

## 风险预记

- M4 的 simdgroup_matrix 若在硬件上仍走同一批标量 FMA 管线（无专用阵列），
  收益可能只来自操作数共享/发射带宽——P1 的证伪线就是裁决器。
- B fragment 逐元素解量化不如 qmv_wide 的 8 值子块摊薄，ALU 省下的可能被解量化
  吃回一部分——P1 的 ≤1.15× 已把这部分留了余量。
- 逐 lane 字节载入同 cacheline 高冗余，依赖 L1 合并；若实测带宽异常高（P4 触发）
  说明测到缓存而非真流量。
